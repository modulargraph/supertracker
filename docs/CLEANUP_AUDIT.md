# Cleanup audit — dead code and refactor opportunities

Read-only audit, 25 October 2026, against `master` at `539add1` plus the working tree at that time. Other agents were editing `AudioHost.swift`, `LibraryService.swift`, `KitLibrary.swift`, `TrackerEngine.cpp/.h`, `kit-browser.*` and several engine tests during the audit, so line numbers in those files may have moved by a few lines. Nothing was deleted or changed except this file.

**Status, 26 October 2026.** The test, tool, doc and on-disk findings are done: items 1.1, 1.9, 1.10 and 1.11, and 2.5 to 2.9 (passing orphan tests wired into `scripts/test-steps.sh`, broken ones deleted, temp-folder traps added, `prototypes/` removed, stale handoff, plan and review docs deleted, evidence links into `test-output/` and `build/` removed). The tempo-map and frozen-replay findings (1.2, 1.3, 2.1, 2.3) are being handled by removing that code; their tests go with it. File references below describe the tree at the time of the audit.

**Method.** Swift: a token-reference scan over `Sources/`, `tests/`, `tools/`, `scripts/` and `Resources/Web`, with production uses kept separate from self-test uses (`Native*.swift`, except `NativeContextMenu.swift`, which is production code). I also ran a full `swift build -c debug` in an isolated scratch path. JS: a node script that lists every function and `window.ST*` export member and counts references across the web, Swift (JS inside `evaluateJavaScript` strings), tests and tools. C API: each `st_*` symbol in the public headers checked for Swift callers. CSS: every class selector checked against JS, HTML and Swift. Bridge: every `case "x.y"` command checked for a quoted string in `Resources/Web`. Orphan tests: each one compiled and run in a scratch directory.

**Confidence:** **H** = no reference found by any of these methods, including string, selector and self-test references. **M** = no production reference, but a test, a doc or a pending feature depends on it. **L** = a judgment call.
