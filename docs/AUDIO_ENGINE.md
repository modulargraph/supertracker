# Original tracker audio engine

The engine is the Rust crate `crates/tracker-engine` (module `tracker_engine::engine`). It uses only the standard library, with no third-party synthesis or DSP framework: the oscillator, sampler, sequencer, envelopes, modulation, filters, bit reduction, distortion, delay and reverb are original DSP code in this repository. The crate does no I/O; devices, the mixer graph and plug-ins belong to the host (`st-audio`). There is no C interface and no C++ implementation any more.

## The API in brief

| Item | What it is |
|---|---|
| `engine::Engine::new(sample_rate)` | Creates an engine (8–384 kHz). `Engine::split()` (or `engine::host::split(sample_rate)`) takes it apart into the three handles below; `Engine::halves()` lends them for single-threaded use. |
| `engine::host::ControlHalf` | The control thread's handle. `parts()` returns `(&mut Control, &Shared, sample_rate)`; every project setter and command is a method of `Control` (`engine/edits.rs`, `engine/control.rs`), those that reach the render side take the `&Shared` next to them. `commit()` publishes; `pop_input_ack()` reads input acknowledgements. |
| `engine::host::RenderHalf` | The audio thread's handle: `render`, `advance`, `render_bus`, `render_channel`, `prepare_history`, `render_block` + `block()`, `pop_event`, `clock_span`, `freeze_span`, `capture_transport`, `restore_transport`, `forget_external_voices`. |
| `engine::host::StatusHandle` | Clonable, any thread: `status()`, `track_peak`, `refresh_automation`, `reset_render_cache`, `watch_voice_positions`, `voice_positions`. |
| `engine::abi` | The plain data and constants: `STTrack`, `STInstrument`, `STStep`, `STEvent`, `STStatus` (with `transport_playing()` and `count_in_shown()`), `STTransportState`, `ST_*` constants, `default_track/instrument/step()`, and the bus arithmetic `return_bus`, `channel_count`, `output_bus_count`, `channel_output_bus`, `instrument_capacity`. |

Each half exists once per engine and needs `&mut self`, so the type system keeps control calls on one thread and render calls on another; `engine/host.rs` documents why the handles may cross threads. Names below are those of this API.

## Rendering and thread ownership

The engine renders stereo floating-point PCM at its construction sample rate. There is one bus per track (never fewer than 16) and one stereo send-return/metronome bus after them (`return_bus(track_count)`, bus max(16, track count)). `RenderHalf::render` mixes those directly for standalone and offline rendering. `RenderHalf::render_bus` (and `render_channel`, which addresses a bus by logical channel) retains every bus in a 65,536-frame timestamp ring. Serialized graph pulls may overlap and have different frame counts—for example, an AU may request 4,097 source frames while another branch requests 4,096. Only an uncached suffix advances the sequencer and DSP; existing ranges are copied without advancing music twice. Requests up to 65,536 frames are generated internally in chunks of 4,096; a negative bus, a longer request or a range that overflows the timestamp returns silence without rendering, and a request of no frames does nothing. `prepare_history` extends the history without copying anything out. Events retain offsets relative to the requesting range, including reused prefixes. Requests older than retained history return silence for their unavailable prefix. A forward timestamp discontinuity larger than retained history requires an explicit reset rather than unbounded real-time catch-up rendering. Direct stereo rendering accepts larger blocks. `RenderHalf::render_block` is the Rust host's path: it renders the next block (at most 4,096 frames) into the per-bus block buffers, which `block()` exposes without a copy, and keeps clock history but no bus history.

One serial control thread (the holder of the `ControlHalf`) owns project setters and sample decoding. `Control::begin_update` / setters / `Control::commit` publish a complete immutable project through an atomic pointer; a commit that fails validation returns the reason as `Err(String)` and keeps both the published project and the draft. The callback adopts the latest snapshot at the next buffer boundary and retires the old one on a lock-free list. `Control::collect`, called from the control thread, destroys retired snapshots and unreferenced sample allocations. Sample references survive project edits while existing voices still use their PCM. Loading PCM (`edits::Pcm`: a left slice, an optional right slice and their rate) always copies the caller's buffers and is validated before anything is stored; passing `None` explicitly clears a slot.

Transport, live note, panic and pitch-bend commands use a bounded single-producer/single-consumer ring. The renderer allocates no memory, deletes no heap objects and takes no locks. The host serializes bus pulls by owning the one `RenderHalf`. Status fields and peaks use atomics. Dropped command/event counters make queue pressure observable. The 65,536-entry event queue reserves note-termination capacity: under extreme pressure automation is shed first, then new note-ons are rejected without creating an external voice; accepted notes retain space for their note-offs, including panic and voice stealing. The engine is destroyed when its last handle is dropped. Call `StatusHandle::reset_render_cache` while the graph is stopped before a graph restart or a manual-render pass resets sample timestamps. Ordinary project, note and transport commands never invalidate already-rendered ranges belonging to another branch; they take effect at the next newly generated suffix. Cache reset changes only the timestamp epoch, leaving queued music commands and effect state intact.

Host routing is opt-in through `Control::set_host_mixing` (or `set_host_mixing_tracks`, which takes the computational mask as 64-bit words for any track count); without it the engine keeps its own summed signal path. In host mode, the track buses contain native instrument DSP and timeline clips before track volume/pan, audible mute/solo, master gain and legacy sends. Instrument gain/pan, envelopes, filters and instrument automation still apply. The low 16 bits of the computational mask gate raw PCM and AU note generation independently of audible mute/solo; removing a bit terminates existing AU notes. Native voices keep advancing while excluded, so their envelopes and LFOs do not freeze. Excluded clips skip PCM mixing. Hardware MIDI keeps legacy mute/solo gating independently of this mask because the external device is outside the host audio graph. Bus 16 (the return bus) contains only the metronome, without master gain. Switching between host and legacy modes clears the legacy delay/reverb state so an old tail cannot reappear. Raw track peaks measure those unscaled buses; the host owns final routing, faders, sends and output metering.

Host-owned automation uses `Control::add_host_automation_point`, with destination 0–2047 (`ST_MAX_HOST_DESTINATIONS`), an opaque 64-bit address and raw finite double values. Each pattern supports 256 host lanes in addition to 256 native lanes, each with up to 4096 points. Destinations are mapped by the host to persistent group/return/master/route/plug-in identities. These lanes emit `ST_EVENT_HOST_PARAMETER` (type 5), with `target=destination`, `track=-1` and unchanged address/value; they never mutate native DSP. Stepped values change at exact sample boundaries, including fractional rows; linear values use the existing 32-frame event interval. Seek, project/pattern changes and automation refresh re-emit the current host values. `clear_automation` clears both lane families. The host supplies timed default values when generic lanes disappear because their destination defaults are not part of the native engine. Host automation shares the event queue's note-off reserve and bounded delivery retries.

`RenderHalf::capture_transport` and `RenderHalf::restore_transport` are exclusive stopped-graph operations for temporary offline export. The host must stop the graph and wait for every render/event reader to finish before calling them. Capture adopts pending project/control changes, including a queued Stop, without rendering a sample. The ephemeral `STTransportState` stores exact frame-domain row timing, song/pattern mode and play state; `STStatus::song_mode` exposes the published mode. Restore clears temporary voices, effect tails and scheduled notes, restores the exact clock/cursor, and resumes only when both the checkpoint was playing and the caller permits it. The host owns cancellation: pass `resume = false` for a user Stop or cancelled export, since an internal export-tail Stop is not user intent. Both operations discard queued events and invalidate cached audio; the host must separately stop AU and external MIDI notes. Current automation is re-emitted on the next actual render. Native/plug-in voice state, current-row step locks and effect tails are not checkpointed; a mid-row resume waits for the next row to trigger new notes. Metronome timing resumes at the next actual beat, without an extra mid-beat click. Restore sanitizes public fields and assumes the original project/sample rate has been restored first.

Native voice rendering visits active slots through a fixed bitset in their original summation order. Exact-input caches reuse oscillator pitch conversion, sample playback rate, drive normalization and filter coefficients; the two stereo channels share coefficients while retaining separate filter states. Changing automation or modulation inputs invalidates these caches immediately. Envelopes and LFO phases still advance every sample, including when their amount is zero. No reduced control rate, approximation or smoothing shortcut is used for these optimizations.

## Music behavior

- No fixed track count (per-track tables sized at commit; 1024 sanity bound), 64 instrument slots, 256 patterns, 256 rows per pattern, 4096 song sequence entries, and 256 active voices.
- Chords hold up to eight notes. Voice modes include poly, mono and legato. Matching nonzero choke groups cut previous voices. Native live pitch bend is additive to instrument tuning and track pitch automation.
- Native instruments use sine, polyBLEP saw and square, triangle, or noise oscillators, or decoded stereo PCM. Native sample modes include one-shot, forward loop, reverse, ping-pong loop, equal/manual slices, wavetable and overlapping Hann-window granular playback.
- Manual slice points are normalized within the selected sample region. Zero is included automatically; the selected MIDI note relative to root note chooses the slice. Wavetable playback uses a movable window up to 2048 samples. Granular size and position are adjustable; two grains overlap with complementary windows.
- The `slice` step effect (`ST_FX_SLICE=15`) selects slice 1–128, clamped to the last available slice. It uses equal or manual markers and plays that region once; notes and chords transpose the selected slice relative to the root note. Without this effect, Slice mode retains ascending-note slice selection. A slice effect in an effects-only cell does not retrigger a note.
- `Control::preview_step` auditions a copied step/chord snapshot for a 0.03–2 second gate without moving transport. Preview voices have independent ownership; a new preview or negative preview note stops only prior previews. Preview ignores probability/ratchet/microtiming and honors velocity, chord, slice, reverse, offset and pitch. Native legato and note-up do not adopt/release preview voices. AU/MIDI preview is suppressed if a real note already uses the same destination/pitch; an incoming real note ends a colliding preview before starting.
- A sample instrument may have up to 128 key/velocity zones. The first matching zone selects its sample, root note, gain and tuning. Notes outside all configured zones are silent.
- Each native voice has amplitude ADSR, an independent filter ADSR, a topology-preserving state-variable low/high/band-pass filter, resonance, drive, bit reduction, stereo balance, and two LFOs. Filter-envelope amount is −48 to +48 semitones, applied exponentially to cutoff; its attack/decay/sustain/release progresses independently of the amplitude envelope, and note-off captures each envelope's current level. Mono mode retriggers both envelopes; legato preserves both.
- LFO free rates are Hz and depths are normalized 0–1. Each independently selects sine, triangle, saw, square, or deterministic random sample-and-hold, and routes to cutoff (±4 octaves), pitch (±12 semitones), volume (tremolo attenuation), pan (±1), or sample position (±0.5 of the region). Position modulation scans the playback read head, wavetable window or granular center without changing stored sample bounds. LFOs reset phase on a fresh voice and preserve phase for legato. Random sources use independent per-voice generators, separate from oscillator noise. Both routes combine before destination clamping. Each slot optionally syncs to project tempo using `lfo_sync` / `lfo2_sync` and `lfo_beats` / `lfo2_beats`, measured in quarter-note beats per cycle. Defaults are false and 1; periods range from 1/64 to 64 beats. Examples are eighth note = 0.5, dotted eighth = 0.75, eighth-note triplet = 1/3, and a four-quarter bar = 4. The effective rate is BPM / (60 × beat period), advanced every sample independently of tracker swing or meter. Phase is per voice, retriggered by a fresh note rather than locked to song position; legato and live tempo, division or sync-toggle edits preserve it. Synced phase advances even with zero depth and free rate zero.
- Modulation defaults preserve an unmodulated instrument: `filter_attack = 0.005`, `filter_decay = 0.2`, `filter_sustain = 0`, `filter_release = 0.2`, `filter_env_amount = 0`, both LFO rates/depths zero, and cutoff/sine routing. `lfo_rate`/`lfo_depth` are LFO 1; the further fields are `lfo_target`, `lfo_shape`, `lfo2_rate`, `lfo2_depth`, `lfo2_target`, and `lfo2_shape`. Filter ADSR/amount and LFO 2 rate/depth have automation targets 26–32. Beat-period lanes use targets 33 (`lfo_beats`) and 34 (`lfo2_beats`); the Hz lanes 14/31 retain their units and stored values but do not affect sound while the corresponding sync toggle is enabled. Beat lanes similarly remain inactive while that slot uses free Hz. Toggling sync does not convert or delete either lane. Sync toggles are instrument settings, not automation targets.
- Step gate, probability, ratchet, sample offset/reverse, arpeggio, pitch glide and positive microtiming are supported. In the legacy path gates and microtiming are rounded to the nearest frame; opt-in mapped timing uses absolute ceil-to-sample boundaries (see `ENGINE_TIMING.md`). Ratchets divide the remaining row after microtiming. Ratchet counts persist per sequencer lane and sound across pattern boundaries and live project edits (Play/Stop/Seek/Panic reset this memory): empty rows repeat the last accepted note/chord, a new note replaces that chord, and another effect command, note-off/cut, zero-velocity note or panic ends repetition. A ratchet-only row can start/reconfigure repeats of the last note; value 1 disables them. Co-located effects apply to the initial row; subsequent empty rows repeat at the retained count without inheriting microtiming. Effect-only reverse changes active sequenced sample voices in place (1 backward, 0 forward); effect-only offset seeks within their selected sample region, measured from their playback direction, without restarting envelopes. Direction and position changes use a 2 ms per-voice continuity correction, including overlapping release tails; repeated changes start from the last corrected output. Reverse note starts use the sampler fade-in even at the file boundary. These playhead commands apply to ordinary sample playback and slices; granular/wavetable synthesis uses its position parameter. OFF/CUT also cancels pending delayed triggers owned by that lane/sound. Probability decisions are deterministic from the engine's seeded generator.
- Empty cells do nothing; note `-1` releases, `-2` cuts, and `-3` applies step effects without triggering or cutting a note.
- Note columns: a track has up to `ST_MAX_NOTE_COLUMNS` (8) note columns. Column 0 is `Control::set_step`; `Control::set_step_column` writes columns 1–7 (note, instrument, velocity, gate; no chord or FX). Extra columns are stored copy-on-write per (pattern, track, column) like column 0 and only rows whose track has them are visited. Each column is its own sequencer lane on the track's channel (lane id `track + column × ST_TRACK_SANITY_LIMIT`): a new note releases only its column's gateless notes, OFF/CUT ends only its column's notes and queued hits, and gates are per column. The row's FX (column 0's FX 1/FX 2 and plug-in locks) apply to the whole row: channel FX as usual, note FX (ratchet, microtiming, offset, reverse, glide, arpeggio, slice) on every column's note, probability as one roll per row. An OFF/CUT row in column 0 carries no note FX for the other columns. Effect-only playhead commands (reverse, offset) steer every column's sounding sample voices. A sticky ratchet continuing through empty rows repeats column 0's note only. AU/MIDI note-offs go out per voice; two columns playing the same pitch on one plug-in follow the rule that a real note first ends the pitch it retriggers.
- Note lifetime: `STStep::gate` is rows of the hit spacing; `gate <= 0` is no gate (tracker semantics). A gateless sequenced voice sounds until the next sequenced note on the same lane starts (that `noteOn` releases it with its envelope, and external instruments get a note-off at that frame), an OFF/CUT, the end of a one-shot region, song end or Stop. Voices that started in the same frame (a chord, or one row's ratchet hit) never release each other, and gated voices are never shortened by a later note. Ratchet repeats of a gateless note each last one repeat spacing. A note on a row also ends that lane's sticky ratchet unless it carries its own Ratchet; only empty rows continue it.
- Live keyboard/MIDI-input voices and sequenced voices have separate ownership. Tracker OFF/CUT, natural song end and automatic song wrap release only sequenced notes; live note-up releases only live notes, including when native voices share the same pitch. Explicit Play, Stop, Seek and Panic release both sources. Mono, legato, choke groups and voice stealing retain their intentional voice-replacement behavior.
- Native step parameter locks override the same automation target for the current row. A lane resumes on the next row. Lanes interpolate linearly or hold points, use parameter-native units, and evaluate inside the renderer. Plugin values are normalized 0–1.
- AU and external MIDI instruments generate timestamped note on/off events with track, instrument and frame offset. The host pops them with `RenderHalf::pop_event` and routes them to plug-in instances or MIDI ports. Stepped plugin and native parameter lanes emit their first value and each actual value change at the exact sample where playback reaches the point, including fractional rows. Unchanged step values are deduplicated; seeking, pattern changes and resuming after a row lock force the appropriate current value. Project publication, pattern transitions and transport positioning first emit timed defaults for track volume/pan/sends and assigned instrument volume/pan on every configured track; active lanes override them at the same sample in FIFO order. Removing a lane therefore restores its configured mixer value without a main-thread AU reset race. Hosts ignore these mix events where no AU instrument exists. `StatusHandle::refresh_automation` uses an independent atomic mailbox callable from any thread, including graph preparation on the audio thread. Requests coalesce and are consumed after ordinary commands at the next uncached frame; they never write the UI producer’s command ring or consume its capacity. The refresh preserves voices and row locks while re-emitting held controls and active lanes after latency/routing changes. Linear lanes emit an initial value and then use a 32-frame control interval. Under event-queue pressure failed deliveries retry at bounded 32-frame intervals. Native DSP lane evaluation remains per-sample. Negative plugin slot `-1` identifies an instrument parameter.
- Swing alternates longer/shorter rows. Song playback follows its sequence and either stops or loops; pattern playback loops the active pattern. Native master sends are a stereo cross-feedback delay and a damped eight-comb/four-allpass reverb. Mute and solo control audible native tracks and new external note triggering.
- Song timeline clips use up to 256 dedicated PCM asset slots and 256 clip placements independently of instrument slots. Clips have absolute quarter-beat start/duration, source offset in seconds, gain, fades and mute; they feed normal track routing and sends. Playback and song export extend beyond the last pattern when clips continue, and song loops restart only after the longest audible clip ends. Seeking resolves the absolute song clock and begins inside a clip at its corresponding source position.
- Meter numerator/denominator controls metronome accents. Tracker lines-per-beat still refers to quarter notes. The host should disable metronome in offline exports.

## Deliberate implementation limits

This version does not implement sample streaming: decoded PCM, timeline audio and all zone samples reside in memory. Timeline audio plays at its original sample rate without musical time stretching; its normal track gain, pan, mute, solo and send automation applies, while note-only instrument parameters do not transform clip PCM. The granular mode is an original two-grain instrument, not a phase-vocoder audio-clip warp engine. Native pitch glide is an exponential semitone offset rather than per-note MPE. No negative microtiming is scheduled before the first row. The metronome has accented clicks but no pre-roll count-in. Native direct stereo rendering clips only values above full scale; the native host owns final AU/output protection. Synth triangles and noise are not oversampled. Editing structural sample mappings changes subsequently triggered voices; existing voices retain safe access to their originally triggered PCM.

AU and external MIDI instruments receive ordinary MIDI note/channel events, without per-note identifiers. If a live note and a sequenced note share the same destination, channel and pitch, their separate engine ownership cannot guarantee independent release in the receiving plugin or device. Distinct pitches retain their independent lifetimes.

## Validation

The engine's tests are Rust tests of the crate and run without the application, a device or a display:

```sh
cd rust
cargo test -p tracker-engine              # debug: overflow and bounds checks on
cargo test -p tracker-engine --release    # the build the recorded PCM hashes and CPU budgets refer to
```

`tests/engine_core_*.rs` and `tests/engine_timing_*.rs` are the deterministic core suites. They cover oscillator pitch/release, exact event timing, chords/ratchets/microtiming, swing/song/seek, probability, automation, all seven sample modes, delay buses, concurrent immutable project updates and PCM replacement, velocity zones/manual slices/clearing, mono/legato/choke/mute, effects-only steps, 256 simultaneous voices over a sustained render, pitch bend, metronome timing, row-lock precedence, sampler edge regressions, and timeline clip start/seek/offset/fades/loop/song-end behavior, live arrangement extension during a clip tail, long gates up to 256 rows, independent filter-envelope dynamics, all five LFO destinations, combined LFO routes, random/block-size determinism, high-numbered modulation automation, mono/legato modulation behavior, repeated note-off, inactive-modulation compatibility and invalid modulation parameter sanitization, both tempo-synced LFOs with straight/dotted/triplet divisions, free-Hz PCM compatibility, independent destinations, maximum synced rate at 8 kHz, live tempo/division/sync-toggle phase continuity, fresh-note/legato behavior, zero-depth phase advancement, beat-period automation and inactive Hz lanes, unequal/overlapping bus pulls, cache rollover/reset, and cached-prefix event offsets/control boundaries, and automation-overflow note-off protection including rejected note-ons, voice stealing and panic, plus exact stepped plug-in/native automation boundaries, fractional-row points, hold deduplication, seek restoration and row-lock resumption, live lane-removal default restoration, unchanged-step FIFO replacement, and latency-plan automation refresh preserving active row locks, and simultaneous control/audio/refresh threads with mailbox coalescing and balanced note events, plus live-note ownership across tracker OFF/CUT, song end and song wrap, native same-pitch release independence and explicit transport stopping. Export-checkpoint coverage includes zero-frame seek positions, queued Stop capture, explicit cancellation, exact fractional Song/Pattern restoration, first-render automation, pattern wrapping, audio-clip tails, malformed input and metronome boundary timing. Host-routing coverage includes raw-versus-unity DSP equality, silent-mask state advancement, plug-in versus hardware MIDI gating, raw clip/metronome behavior, mode-change tail clearing, host lane timing/precision/reset/caps and overflow protection for note-offs.

The other `tests/engine_*.rs` files are the focused suites (freeze timeline and extent, input acknowledgements, many tracks, render budget, wavetable, granular, step effects, song sends, reverse continuity, DSP regressions, parameter bounds), `tests/clock.rs` and `tests/unit_range.rs` test the clock and the unit render cache, and `tests/effects_*.rs` the built-in effects and drum models. A counting global allocator in the test support modules verifies that no heap allocation or free occurs on a thread while it renders. `tests/engine_benchmark.rs` and `tests/engine_dsp_benchmark.rs` render deterministic 16/32/64/256-voice synth and looping-sample scenes, plus two-LFO/filter-envelope/drive and granular scenes; they check finite, audible output and zero render allocations, compare the PCM hashes recorded for each scene, and print CPU and elapsed time. Performance is printed rather than assumed: CPU load, scheduling across performance/efficiency cores and thermal conditions affect the reported throughput, and maximum polyphony is a capacity limit rather than a guarantee for every patch and plug-in combination.


Slice analysis (`sample.analyzeSlices`) runs offline and returns ordered slice starts normalized inside the selected sample region; zero is always present and the end marker is omitted. It measures stereo power and a difference band against a preceding 40 ms energy baseline, rejects falling-energy release edges, and applies sensitivity, minimum spacing and a 128-slice ceiling. Original samples and files remain unchanged. Analysis uses approximately 1 ms windows, widened as necessary to bound the envelope storage at 262,144 windows for long files. The analysis is `st_samples::slicing`, with synthetic kick/snare, sustained-note, antiphase, noise, silence, selection and long-file fixtures in its tests.


The opt-in stepped tempo/meter engine API, retained clock history, mapped checkpoints, and integration limitations are documented in `ENGINE_TIMING.md`. Native timing tests do not constitute hosted AU/VST or audio-device timing acceptance.
